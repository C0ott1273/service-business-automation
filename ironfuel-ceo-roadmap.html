01
The Build Order
CEO's Step-By-Step Build Plan

Build order is the most important strategic decision you'll make. Wrong order = building features nobody uses on top of a leaky retention bucket. This plan follows a single principle: fix the core loop before adding anything else.

🎯
The Core Loop (Never Deviate From This)
Log food → Log weigh-in → Log workout → Get weekly suggestion → Approve it → See results. Every feature you build for the first 6 months must either be this loop, reduce friction in this loop, or make this loop more compelling to return to.
0
BEFORE DAY 1 · Weeks 1–4
Foundation & Team
Before writing a single line of product code

Most founders skip this phase. It's why most startups build the wrong thing.

1
Recruit 50 alpha users from Reddit RIGHT NOW
Post in r/leangains, r/powerlifting, r/MacroFactor, r/loseit. Find people actively cutting who also lift. These are your first 50 users, your user research lab, and your first word-of-mouth vector. DM them personally. Offer lifetime Pro for feedback.
Target: 50 committed alpha users before any code ships
2
Run 20 user interviews — understand the pain, not the feature request
Ask: "Tell me about the last time your cut failed." "What do you watch on the scale that makes you panic?" "What's happened to your lifts when you've dieted before?" "Why did you stop using [app]?" Do NOT ask "what features do you want." Listen for verbs and emotions, not nouns.
Deliverable: A 1-page pain map, not a feature list
3
Hire your critical path: 1 senior React Native dev + 1 backend/Supabase dev
Do not hire a PM yet. You are the PM. Do not hire a designer yet — you have a working UI design system. The only hires that unblock code at this stage are engineers. Both should be full-time. Contractors will kill your velocity.
Budget: $180–240k/yr combined · Look at Toptal or YC talent networks
4
Set up your data model and Supabase project BEFORE any app code
The SQL schema is your product. Get it right before building UI on top of it. Run the full schema from the architecture document. Set up Row Level Security. Set up Edge Function scaffolding. Set up local dev environment with shared config. One bad schema decision now = weeks of migrations later.
Deliverable: Supabase project live, all tables created, RLS enabled
5
Launch a waitlist landing page and start collecting emails today
Single page. Tagline. Email capture. Nothing else. Post it everywhere. Goal is 1,000 waitlist signups before launch. These become your Day 1 cohort. Use Loops or Beehiiv for the email list — you'll want to send weekly "build in public" updates that prime them for the product.
Target: 500 waitlist signups before MVP launch
1
Months 1–3 · Private Beta
The Unbreakable Core
Build only what is required for the core loop to work flawlessly

Your only job in Phase 1 is to make the core loop work so well that your 50 alpha users open the app every day. Not 48 of them. All 50. Nothing else matters.

1
Onboarding flow — 3 minutes or bust
Height, weight, training days, experience level, main lifts. Then: show them their first calorie/protein target immediately. The "aha moment" must happen before they close the app for the first time. If they don't see a number in session 1, you've lost them. Build the personalization quiz, TDEE calculation, and first weigh-in prompt as a single flow.
KPI: Onboarding completion rate ≥ 80%
2
Food logging with USDA API + barcode scanning
Search-first. Barcode second. Recents third. This order matters — most users type before they scan. Cache USDA results aggressively. Build the food cache table from day 1. Speed is everything here: MacroFactor built their entire reputation on logging being 2 taps fewer than competitors. Beat that. Target: food logged in under 20 seconds from open.
KPI: Average food log time under 25 seconds
3
Daily weigh-in + 7-day rolling average visualization
This is the most important screen in the app after nutrition. The rolling average IS your product's core promise — "ignore the noise, trust the trend." Build a beautiful trend chart that makes users feel calm when the scale jumps. The chart needs to visually separate raw daily weight (light, dotted) from the smooth rolling avg (bold, lime). This one chart justifies the entire subscription.
KPI: Users who log weight 4+ days/week retain at 3x rate
4
Lift tracker — session logging with e1RM computation
Exercise name + sets + reps + weight + RPE. One-tap set completion. Auto-populate last session's weights. Compute Epley e1RM on every logged set in the background. Store strength_baselines at end of each week. This powers the Strength Sentinel agent — without this data, the core differentiator doesn't fire. Build it right, not fast.
KPI: 60%+ of users log at least 1 workout in first week
5
Macro Engine — the weekly adaptation algorithm
Deploy as a Supabase Edge Function on a Sunday cron. Rate of change calculation. Decision rules. Protein lock. Carb/fat redistribution. Write to macro_suggestions table with status='pending_user_approval'. Send push notification. The suggestion UI — approve/dismiss — must be the most satisfying interaction in the app. This is your product's payoff moment every Sunday.
KPI: 70%+ of suggestions approved (not dismissed)
6
Strength Retention Score + Performance Dashboard
Compute SRS weekly: mean(e1rm_current / e1rm_baseline) × 100. Display it as the primary metric on the home screen — bigger than weight, bigger than calories. This is the reframe. Most apps show "X lbs lost." IronFuel shows "94% strength retained." That number is your brand promise made tangible. Users screenshot this and share it.
KPI: SRS viewed in ≥ 60% of weekly active sessions
7
Stripe billing + 14-day free trial
Free tier: food logging + weigh-in only. Pro: everything else (adaptive engine, strength tracking, AI coach, recipes). Build the paywall as a feature reveal, not a wall. Show free users what the algorithm would have told them this week — blurred. "Your Macro Engine ran. Upgrade to see your adjustment." The best paywalls create FOMO from the product itself.
KPI: Trial-to-paid conversion ≥ 25%
🚫
Do NOT build in Phase 1
Social features, AI coach, recipe vault, Apple Watch app, progress photos, gamification, friend challenges, leaderboards, wearable integration, or anything else that sounds exciting. Every hour spent on these is an hour not spent making the core loop perfect. Restraint is the CEO's most underrated product skill.

Months 4–6 · Public Launch
Intelligence Layer
Add the features that make the app feel alive and earn media coverage

Phase 1 gave you a functional app. Phase 2 makes it feel like it knows you. This is where IronFuel starts to feel materially different from every competitor.

1
AI Performance Coach — weekly brief via GPT-4o
Sunday 8am cron. Server-side prompt injection of user metrics: rate of change, protein adherence, SRS, compound trends, RPE. 100-word plain-English brief. No fluff, no "great job" — a coach, not a cheerleader. This is the feature users will talk about. "My app writes me a weekly coaching brief based on my actual barbell numbers" is a story that writes itself on Twitter/X and Reddit.
KPI: AI brief open rate ≥ 70% on Sundays
2
Recipe Vault — 50 original recipes at launch
These cannot be generated content. They must be developed, tested, and photographed (or illustrated). Each recipe must earn its place: satiety score, volume score, protein density score. Filter by remaining macros — "show me recipes that fit my dinner budget of 45g protein, 200 kcal." This makes the vault a tool, not a cookbook. The algorithm recommends recipes in your daily feed when you're behind on protein at 3pm.
KPI: Recipe opened from agent feed ≥ 30% of recommendations
3
Recovery Analyst agent + RPE trend monitoring
Track 3-week rolling RPE. Flag rising effort without weight increase. Recommend deload weeks proactively — before the user notices they're burnt out. This is a retention feature disguised as a health feature. Users who get deload recommendations and follow them stay longer, because they're not grinding until failure and quitting.
KPI: Deload recommendation follow-through ≥ 50%
4
PR detection + celebration system
Every new e1RM record triggers a push notification, an in-app animation, and a entry in the user's PR log. Build a "PR during a cut" hall of fame view. This is the emotional payoff of the whole system — proof that the app worked. PRs during a calorie deficit are rare and exciting. Treat every one like a milestone. Users who hit PRs in the app churn at dramatically lower rates.
KPI: PR notification open rate (target 80%+)
5
Protein-first food logging UX
Reorder the food logging experience so protein is always the first thing shown, not calories. When you search "chicken breast," show the protein number in the largest font. When you finish a meal slot, show "38g protein" first, then "420 kcal." This is a UX philosophy decision, not a feature — but it rewires how users think about food. That reframe is itself a retention mechanism.
This is a design sprint, not an engineering sprint
6
Public launch — App Store + Play Store
Product Hunt launch day. Twitter/X fitness community blitz. 5 mid-tier YouTube creators (50k–500k subs) with custom affiliate codes. Reddit launch posts across 8 relevant subs. Press kit targeting fitness journalists. The story: "This app uses your deadlift to adjust your diet." That's the hook. It's unusual enough to get coverage without needing a PR agency.
Target: 2,000 paying subscribers within 60 days of public launch

Months 7–9 · Retention & Depth
Habit Architecture
Engineer the features that turn casual users into lifers

The industry average is 3% day-30 retention. Your goal is 25%+. The only way to get there is by building features specifically engineered around the moments users quit — and intervening before they do.

1
Apple Watch + WearOS app for one-tap logging
43% of fitness app users own wearables. The watch app has one job: log a set. Weight, reps, RPE — from your wrist, in the gym, without pulling out your phone. That's it. No nutrition tracking on watch (too complex), no dashboard. Just set logging. Every second of friction removed from gym logging increases workout data quality, which improves the Strength Sentinel accuracy.
KPI: Watch users log 40% more sets than phone-only users
2
Photo food logging via AI vision (GPT-4o vision)
Point camera at plate → AI estimates food and macros → user confirms or adjusts. This reduces the #1 abandonment cause: logging friction. It will not be perfectly accurate. That's okay — it needs to be good enough that users prefer it to manual entry for ad-hoc meals. Keep barcode scanning as the precision option, photo as the speed option.
KPI: Photo log used in ≥ 20% of food entries
3
Workout template system + progressive overload engine
Let users save and run structured programs (PPL, 5/3/1, etc.). Auto-suggest weight increases based on RPE trend and e1RM progression. "Last week you hit 205×5 at RPE 7.5. Try 210 today." This makes IronFuel a training app, not just a tracker — and makes it compete directly with Strong and Hevy for the lift-tracking market while keeping the nutrition advantage.
KPI: Users with templates log 2x more consistently
4
Cut completion flow + Maintenance Mode transition
When a user reaches their target weight, IronFuel should have a plan. A "Your Cut Is Complete" celebration screen, a transition protocol into maintenance calories, and a new set of targets. Without this, users hit their goal and churn. Maintenance Mode is a full product phase — calorie cycling, reverse dieting, recomp mode. Build the celebration first, the maintenance features second.
This is your most important retention feature at month 4+
5
Progress photo vault (private, encrypted, local-first)
Time-stamped progress photos with body weight overlay. Weekly comparison view. This is the most emotionally resonant feature in any body composition app — the visual proof of transformation. Make it the most beautiful, private, and easy-to-use progress photo experience in any fitness app. Users who use photo logging churn at 40% lower rates (Noom internal data, widely cited).
KPI: 30%+ of users activate photo vault in first month
6
Streak mechanics + "gentle" recovery system
Logging streaks with a deliberately forgiving architecture: one "flex day" per week that doesn't break a streak. "Protein protected" days (logged protein only) count. The streak should reward showing up, not perfection. Users who maintain a 7-day streak are 5x more likely to reach 30 days. The streak is the single highest-leverage retention mechanic available — but only if it's kind.
KPI: 7-day streak rate ≥ 35% of active users

Completely different from MyFitnessPal's social features — less social network, more data community.

When your squat e1RM drops 3%+ across 2 sessions, calories automatically tick up 75 kcal in the next weekly suggestion. This closes the feedback loop between the gym and the kitchen in a way no competitor has implemented. The algorithm isn't just "what does the scale say" — it's "what does the barbell say?"
No competitor has this Core moat Build now

Most apps give you 15 metrics. Users don't know what to do with 15 metrics. IronFuel reduces your entire week to one number: the Cut Health Score (0–100), a weighted composite of: rate of loss (within range?), protein adherence, strength retention, RPE stability, and calorie compliance. One glance tells you if your cut is healthy or not. Green means go. Yellow means watch. Red means change something. This is the dashboard metric users will build habits around checking every Sunday.
MacroFactor has no equivalent Massive retention driver Phase 2

Real-time visualization showing: your current deficit vs. your personal muscle preservation threshold (estimated from your strength trend). Green zone: "Your deficit is sustainable." Yellow zone: "Your strength is showing early stress signals — consider adding 100 kcal." Red zone: "This deficit is too aggressive for your training load. You are losing muscle." No other app tells users this. It turns abstract calorie math into an actionable safety meter. Users stay longer because they trust the app is protecting them.

The app knows when you train (from workout logs). It automatically creates pre- and post-workout meal windows and suggests how to distribute your carbs and protein around those sessions. "You lift at 6pm. Try to have 40g carbs by 5pm and 50g protein within 90 minutes post-workout." Most apps log food after the fact. IronFuel tells you what to eat and when, before you eat it. What Will Kill You
Retention Risks & Countermeasures

The industry baseline is 3% day-30 retention. 90% of fitness app users are gone in 6 months. These are not abstract risks — they are predictable failure modes with known solutions. Address them before they hit.

CRITICAL
Log Fatigue
The Failure Mode
User has one busy day, skips logging, feels guilt, doesn't open the app, streak breaks, churn. 71% of users abandon apps in month 3. This is the primary cause. Manual food logging is the most friction-heavy daily task in any health app.
The Countermeasure
Photo logging reduces friction by 80%. Quick Log mode ("hit protein today" = 1 tap). Flex days in streak mechanics. Recents auto-fill common meals in 2 taps. Design for the busy day, not the perfect day.
CRITICAL
Stalled Scale
The Failure Mode
User sees no weight change for 10 days. Concludes the app doesn't work. Quits. Most users misread water weight as fat retention. This is a perception problem, not a product problem — but perception kills subscriptions the same way.
The Countermeasure
The rolling average chart is the intervention. When scale stalls, the AI coach sends a targeted brief explaining water weight. Reframe the win: "Your bench went up. Your body is working." Celebrate strength while explaining the scale. IronFuel's dual metric system (weight + strength) is built for exactly this moment.
HIGH
Lift Log Dropout
The Failure Mode
User logs lifts for 2 weeks, then stops. The Strength Sentinel goes dark. The entire core differentiation of the product breaks. Calorie adjustments revert to weight-only. The app becomes a less-good MacroFactor.
The Countermeasure
Apple Watch app for in-gym one-tap logging. Strong/Hevy import for users who prefer those apps. Agent nudge after 7 days without a session: "Strength data is missing — your algorithm is running blind." Frame it as data quality, not guilt.
HIGH
Goal Achievement Churn
The Failure Mode
User hits target weight. Cut is over. App loses its purpose. User cancels subscription because "I'm done." This is the single most predictable and preventable churn event in the entire lifecycle.
The Countermeasure
Maintenance Mode must ship before month 7. Cut completion screen with a clear narrative: "This is where most people fail — because they have no plan for what comes next. IronFuel does." Reverse diet protocol, maintenance calorie targets, and Bulk Mode onboarding all ready at the moment of goal achievement.
HIGH
MacroFactor Workouts Launch
The Failure Mode
MacroFactor ships a full workout tracking product with their existing nutrition algorithm integrated. They have 50,000+ existing users. They own the "best algorithm + best logging" position. IronFuel's core value proposition is suddenly table stakes.
The Countermeasure
Speed is the answer. Ship before they do. Own the "strength-first" brand loudly — MacroFactor can't pivot their identity. Build content, community, and coach partnerships that create switching costs before they compete. The window is 12–18 months. This is why urgency is non-negotiable.
MEDIUM
Recipe Vault Irrelevance
The Failure Mode
Recipes aren't tested, don't taste good, or don't match user preferences. The vault becomes a feature nobody opens. "The recipe section is fine, I just never use it." This wastes significant content investment and removes a key retention touchpoint.
The Countermeasure
Every recipe must be tested IRL — not GPT-generated. Use a part-time recipe developer. Filter vault by remaining macros ("what fits my dinner budget"). Surface recipes in the agent feed when protein is at risk. Make them indistinguishable from content you'd follow on a great food creator's Instagram.

Speed is a strategic weapon right now. MacroFactor Workouts is in development. You have 12–18 months to own the "strength + nutrition" positioning before they have a polished product. Slow is not an option.
→
The Strength Retention Score must be front and center from day 1. It is the brand in a number. It is the reframe from "weight loss app" to "performance app." Everything in the product narrative flows from it.
→
Never auto-apply an algorithm change. Every macro suggestion requires user approval. This is not just a safety decision — it's the trust architecture that makes users feel in control. Remove this and you remove the trust that makes the whole system work.
→
Build for the 18-month user, not the 18-day user. Every feature decision should be tested against: "Does this help someone who uses IronFuel through an entire cut, into maintenance, and through their next bulk?" If yes — prioritize it. If it only helps someone in week 1, deprioritize it.
